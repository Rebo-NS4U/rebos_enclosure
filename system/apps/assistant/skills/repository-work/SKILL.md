GitHub workflow: For all GitHub-related project work in this assistant, find the owning Git checkout and verify its remote before editing. Work in the repository first and keep applicable installed files, installer payload, dependencies, documentation and tests synchronized during the task. For Enclosure integrations, check ~/rebos_enclosure first, then ~/code/rebos_enclosure and resolved installed symlink targets; verify the owning checkout with git rev-parse --show-toplevel and git remote -v, then read its AGENTS.md. Installed copies may live under ~/.local/share/enclosure without .git; a missing .git there does not mean the project has no repository. Map assistant to system/apps/assistant, shell to system/apps/shell and media to system/apps/media. Before finishing, compare task-related installed files with tracked source and recover any missed focused changes into the checkout. The user authorizes automatically committing tested task-scoped changes locally to the verified existing repository; follow its branch/PR policy and preserve unrelated work. Ask only when a new repository's destination or visibility is unclear. Never force-push, include secrets or personal state, or bypass sandbox approvals. Do not push automatically. Push only when the user explicitly requests it or uses the Push button in GitHub Settings. Report verification and the local commit; clearly state when changes have not been pushed. Create releases when requested.

GitHub network access: Dweebo enables network access in Codex workspace mode while retaining workspace file protections and tool approvals. Try the normal git or gh command first. Host or administrator restrictions can still block access. For GitHub DNS failures (Could not resolve host), blocked connections, or a gh auth status failure in that sandbox, request the execution tool's supported network approval for the exact git or gh command and retry after approval. For Codex exec_command use sandbox_permissions=require_escalated with a specific justification when that option is available. Task authorization to push does not replace a tool approval. If approval is unavailable or rejected, report the exact blocker and give the user the command to run. A sandboxed gh auth status failure does not establish an invalid credential. Never log out, delete credentials, or start reauthentication based on that failure; verify authentication only after network access succeeds.

---
name: symphony-acceptance
description: Execute a supplied bounded issue with acceptance evidence and a review handoff. Skip ordinary chat and unsupplied issue-tracker automation.
---

Read the supplied issue and repository workflow before making a worktree. Build a small acceptance ledger: criterion, implementation location, verification command or observation, and status. Use connected GitHub tools for GitHub issues; discover another tracker only when the supplied issue needs it. Do not invent an issue, tracker state or an account connection.

Resolve eligibility and dependencies from the actual tracker if available. If unavailable, preserve the supplied scope and label eligibility unverified. Keep worktree creation inside the configured workspace root and preserve existing worktrees. Follow the profile's bounded retry and approval policies.

For each criterion, record actual evidence. Separate implemented, verified, blocked and not requested. A passing test suite does not prove criteria the tests do not cover. Recheck issue status before handoff where a tracker is connected. Include the worktree, branch, local commit, checks and remaining criteria. Do not push or mutate tracker state without authorization.
